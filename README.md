# DSA4213 Assignment 1 — Language Models, Embeddings, and Representations

**Guiding question:** does better next-token prediction lead to better downstream representations?

| Part | What | Entry point |
|---|---|---|
| I | n-gram (KN) vs RNN vs LSTM vs Transformer on WikiText-2 | `run_ngram.py`, `run_lm.py` |
| II | LSTM with random-trainable / own Skip-gram (frozen) / GloVe (frozen) embeddings | `train_word2vec.py`, `run_lm.py` |
| III | Frozen LM features (last vs mean pooling, LSTM vs Transformer) + logistic regression on AG News | `run_downstream.py`, `part3_bootstrap.py` |

## Data

- **WikiText-2** (`Salesforce/wikitext`, config `wikitext-2-v1`) via HuggingFace `datasets` — Parts I & II. Preprocessing: lowercase, whitespace tokens, one `<eos>` per line, vocab built from train split only (rare words already mapped to `<unk>` by the dataset).
- **GloVe 6B 100d** (`glove-wiki-gigaword-100`) via `gensim.downloader` — Part II.
- **AG News** (`fancyzhx/ag_news`) via HuggingFace `datasets` — Part III; stratified 10k train / 2k val subset from the train split, 2k test subset from the test split.

All datasets are downloaded automatically on first run; nothing is redistributed in this repo.

## Reproduce

```bash
bash scripts/run_all.sh
```

Takes ~2–3 h on an Apple M5 (MPS). Or step by step — see the commands in `scripts/run_all.sh`.
Smoke test a model with `python scripts/run_lm.py --config configs/part1_lstm.yaml --epochs 1 --suffix _smoke`,
then Part III on those checkpoints with `python scripts/run_downstream.py --config configs/part3.yaml --lm-suffix _smoke`.

## Evaluation protocol (common to all LMs)

- Test/valid streams are cut into windows of 65 tokens overlapping by one, so every target `ids[1:]` is scored exactly once; the last window is right-padded and padding is excluded from the loss.
- No hidden state is carried across windows: every model (including the n-gram, whose context is clipped to the window) predicts each target from at most the preceding 64 in-window tokens.
- Inference cost: forward-only over the same first 50 test batches (32 × 64), after 5 warm-up batches, with device synchronisation around the timed region.
- Generation: same 5 prompts (`configs/prompts.txt`), top-k = 40, T = 0.8, 40 new tokens, per-prompt seed `123 + i`; only `<pad>` is banned.

## Seeds and configuration

- Global seed `42` (`configs/base.yaml`), generation seed `123`; set via `src.utils.set_seed`. The model is re-seeded right before construction so all embedding settings share the same initialisation stream.
- Word2Vec uses one worker thread and `PYTHONHASHSEED=0` (set in `run_all.sh`) for determinism.
- MPS kernels are not bit-for-bit deterministic, so neural results may vary slightly in the last digits between runs.
- All hyperparameters live in `configs/`; each run copies its resolved config into its metrics JSON.
